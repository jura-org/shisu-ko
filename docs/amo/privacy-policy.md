**Shisu-ko privacy policy**

Shisu-ko is a Firefox extension that shows live Japanese subtitles on YouTube. It works together with a companion server that you install and run on your own computer. The developer operates no servers, has no accounts and receives no data from you. This policy lists everything the extension exchanges with other programs and what those programs do with it.

**What the extension sends, and to whom**

To the Shisu-ko server on your computer (http://127.0.0.1:8790 by default; the address is a setting): the id and page address of the YouTube video you are watching, your current playback position and whether the video is paused, the time of the last subtitle you received, the name of the transcription model you chose in the popup (empty for the server's default), and your mining settings from the popup (whether new cards are filled automatically, the Anki field names for the picture, audio, sentence and word, the audio padding and format), about once per second while a video is playing and the extension is switched on. While one of the two word-colour options is on, the same request also names the deck those options look at (empty for "Automatic"), the two field names they read the word and the pitch accent from, and a token for the deck data the extension already holds; after an update from version 0.22.0 or older, it also names, until the server has answered once, the deck the extension remembered for "Automatic", which it then deletes. When you mine a line by hand (Alt+Shift+M or a pickaxe), the next of those requests also names that line, until the server answers it. Nothing else is sent, and nothing is sent while the master switch in the popup is off.

To Anki: nothing. The extension does not contact Anki or the AnkiConnect add-on; mining and the word colours are the server's (below). When you mine a line yourself and the server reports that Anki is not running (or that it mines nothing), the extension saves that line's audio, which it gets from the server on your computer, and a picture of the video taken as you mined, to the shisu-ko-mining folder in your Downloads; it saves no other files.

To a helper program on your computer, only when you click the Start server button in the popup, and only after Firefox has asked you for permission to exchange messages with it: a request to start the companion server. The helper is part of the same project, installed by the server's setup; it receives nothing else from the extension and starts nothing but that server. The extension remembers such a request for the browser session, so that reopening the popup does not start a second server: the record (the helper's answer and a time) is ignored after 90 seconds, cleared once the server answers or the next request replaces it, and gone when the browser session ends; it is never written to disk.

To GitHub, or any other remote service: nothing. The extension learns of a newer release from the server on your computer, which asks GitHub itself (below).

To youtube.com: nothing beyond what the page itself does. The extension reads the player's playback state on the page in order to place the subtitles; it does not modify your YouTube account, comments or history.

The extension makes no request beyond your own computer: it never contacts the developer, GitHub or any other remote service, loads no remote code and contains no analytics, telemetry or advertising.

**What the companion server does on the network**

The server is a separate program from the same project, under your control. When the extension reports a video, the server downloads that video's audio track from YouTube with yt-dlp and transcribes it locally with Whisper. The server's setup downloads the speech-recognition model you choose there (Whisper large-v3, large-v3-turbo on an Apple GPU, or small) from Hugging Face; the server itself downloads a model from Hugging Face when it starts without the chosen one on disk (setup's download failed or was interrupted) and when you pick a model in the popup that is not on your computer yet. It stores the audio, the transcription cache and the model under ~/.shisu-ko on your computer. If you allow it (at setup, with --save-cookies-from-browser, or by starting it with --cookies-from-browser or --cookies), it sends YouTube that browser's YouTube cookies, which carry its YouTube sign-in (or the cookies held in that cookies file), with every download, so that YouTube also hands out videos it refuses without a sign-in; it does not do so otherwise. Unlike Firefox, yt-dlp does not keep Firefox's contexts apart: the YouTube cookies of every Multi-Account Container, and those that YouTube players embedded in other sites keep, go into one set, so with different YouTube accounts signed in in different containers the server may send another account's cookies instead of the default one's, or a mix of them. To get the cookies, yt-dlp reads the browser's whole cookie store, every site's cookies with their values, for each download (and whenever a live stream's address is renewed), and once more when you allow it, to check that the store holds YouTube cookies. It reads a copy of the store's file, which it writes into your system's temporary folder and deletes as soon as it has read it; if the server is stopped abruptly in that moment, the copy can stay there. It sends each site only that site's own cookies: YouTube's to YouTube and, only if you also start the server with --allow-remote-ejs, GitHub's to GitHub, from where yt-dlp then fetches its challenge-solver script. No cookie goes anywhere else. Unless it is started with --anki-sync off, the server also watches Anki through AnkiConnect: every 15 seconds (every 3 seconds while a video you mine from with automatic filling plays, every second for up to two minutes while it is paused) it asks for the ids of the notes added today and yesterday, and a minute after new ones appear it asks Anki to sync, which makes Anki send your collection's changes to your own AnkiWeb account, as its Sync button does; the server itself sends nothing to AnkiWeb. Unless it is started with --mine off, the server also mines through AnkiConnect: when a note appears that a video you are watching explains (its sentence matches a subtitle line), or when you mine a line by hand, it writes an MP3 or WAV clip of that line, a picture of the video at that line and, for a mine by hand into an empty sentence field, the line's text into the note's empty fields, under the field names the extension sent; when the note's sentence is a piece of that line, it replaces it with the whole line. For the picture it asks YouTube, through yt-dlp and with the same cookies as the audio download, for the address of the video's picture stream once per video (kept four hours) and reads one frame from it; with --mine-picture off it does not. While a video you mine from with automatic filling plays and Anki answers, the server already cuts the clip and reads the frame of each line you watch, so that a card made from it is filled at once. It keeps them for the last ten lines of the last three such videos, in memory only, and drops a video's a minute after its last request. While a client asks for the word colours ("Colour words by their Anki card" or "Overbar by pitch accent" in the popup, both off unless you turn them on, or the portal's Word colours), the server reads one deck through AnkiConnect, the one named or else the one the last card it mined into went to: the ids of its notes, grouped by the state of their cards (new, learning, learned, suspended), and the fields of those notes, of which it keeps in memory the word, its kana reading, the pitch accent pattern and the time of the note's last edit, and sends the extension each card's word, reading, state and pitch accent; while a video is open it asks Anki again every half minute for what changed. For the popup's deck list it asks Anki for the names of your decks. It remembers the deck of the last card it mined into (its name, the note's id and a time) in ~/.shisu-ko/anki-deck.json. Nothing in Anki is changed by this. Unless it is started with --update-check off (or SHISUKO_NO_UPDATE_CHECK=1), the server also asks GitHub (https://api.github.com), where the project is published, for the newest release of Shisu-ko, so that the extension can tell you when the server or the extension is out of date and, if you ask, have the server update itself: once a day (soon after a start whose last check is over a day old; a restart within the day asks nothing), and after a failed request again in 15 minutes, an hour, then every six hours. The request is anonymous: it carries no token, cookie, account or identifier, only a User-Agent naming Shisu-ko and its version, and nothing about you or the videos you watch. GitHub sees it like any request (your IP address), and GitHub's own privacy statement applies to that. The answer (the release's version, its page address, the download address of the extension package, its publication date, and the time and outcome of the check) is stored in ~/.shisu-ko/update-check.json and reported to the extension. The server downloads and installs nothing from that answer; an update happens only when you click Update, through the server's own launcher. The server accepts requests only from this extension and from pages served on your own computer.

**What the extension stores**

Your settings (subtitle style and font, transcription model, shortcuts behaviour, the server's address, Anki field names, the word-colour options and the deck they look at) and the last release check the server reported (the newest version, its page address, the download address of the extension package, its publication date, when the server checked, or why its check failed) are stored in Firefox's extension storage on your computer and nowhere else. Uninstalling the extension removes them. For the browser session only, the extension also remembers which release it has notified you about, which one you clicked "Not now" for, and an update of the server that is under way; while a word-colour option is on, it holds in memory what the server sent about the deck (per card: the word, its reading, the state and the pitch accent pattern), which is gone when the browser ends its background page. The extension keeps no history of the videos you watched.

**Children, sale and sharing of data**

The extension collects no personal data, so there is nothing to sell, share or profile. It is not directed at children.
